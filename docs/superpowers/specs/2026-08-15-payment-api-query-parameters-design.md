# 支付接口查询参数适配

## 目标

使前端支付 API 调用与 2026-08-15 的后端 OpenAPI 文档一致，避免服务端因未收到查询参数而拒绝创建或确认支付。

## 范围

- `POST /api/pay/create`：将 `orderNo` 和可选的 `payType` 作为查询参数发送。
- `POST /api/pay/confirm`：将 `paymentNo` 作为查询参数发送。
- 保持现有函数名称、调用参数和返回值不变，因此页面层无需调整。
- 为 API 封装增加测试，验证请求方法、路径、空请求体及参数位置。

## 不在范围内

- 不调整其他已与文档一致的 API。
- 不修改支付页面或新增支付流程。
- 不改变全局响应处理与鉴权策略。

## 验证

测试将替换 API 模块依赖的请求客户端，断言 `createPayment` 和 `confirmPayment` 均使用 POST、请求体为 `null`，且参数位于 Axios 配置的 `params` 对象中。随后执行完整测试套件和生产构建。
