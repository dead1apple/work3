# 用户端交易闭环收尾实施计划

**目标：** 在购物车后端恢复后，完成并验证“浏览商品 → 加购/立即购买 → 提交订单 → 模拟支付 → 查看订单 → 确认收货 → 按订单商品评价”的用户端闭环。

**接口基线：** 2026-08-23 已从当前 OpenAPI 核对 `/api/cart`、`/api/orders`、`/api/orders/buy-now`、`/api/pay/*`、`/api/orders/review`、`/api/categories/tree` 与 `/api/products` 均已定义。购物车订单 DTO 使用 `cartIds`，评价图片使用逗号分隔字符串，`isAnonymous` 使用 0/1，支付方式使用数字 1/2/3。

## 执行批次

### 1. 购物车结算与订单创建

- 清除“购物车后端未恢复”的静态限制，仅在实时加载失败时显示可重试错误。
- 保持 `cartIds`、`addressId`、可选 `couponId`、`remark` 的严格请求边界。
- 订单创建成功后重新拉取服务端购物车，刷新导航角标；刷新失败不能把已创建订单误报为失败。
- 防止重复提交，订单已创建但跳转失败时保持终态并引导用户去订单列表。

### 2. 支付、订单状态与评价闭环

- 继续使用数字 `payType`，兼容未支付、处理中、成功、失败响应。
- 创建支付单或确认结果不确定时进入轮询，不把不确定状态误报为失败。
- 订单操作严格按状态开放：待付款取消/支付、待收货确认、完成后评价/删除。
- 评价从订单商品进入，提交 `orderItemId`、1–5 星、逗号图片字符串与 0/1 匿名值。

### 3. 首页、分类与商品浏览收尾

- 首页与分类树统一跳转商品结果页并携带真实分类 ID。
- 商品详情保持非笛卡尔 SKU 可选性与库存校验。
- 商品图片归一化兼容数组、逗号字符串和 `data:` URL，避免生成非法资源请求。

### 4. 验收

- 运行全部 Node 单元测试。
- 运行桌面 1440px 与移动 390px 的 Playwright 端到端套件。
- 运行 Vite 生产构建。
- 检查最终 diff，确认无管理端扩展、无本地模拟订单数据、无遗留“后端未恢复”文案。
